# TruthTrace Deployment & Hosting Guide 🚀

TruthTrace is designed to deploy entirely on **100% free tiers**:
- **Frontend Dashboard:** Hosted on **GitHub Pages** ([https://sham-b.github.io/Truthtrace/](https://sham-b.github.io/Truthtrace/))
- **Backend API:** Hosted as a Python Web Service on **Render Free Tier** via Infrastructure-as-Code Blueprint (`render.yaml`).

---

## 🏗️ Architecture & Free Tier Constraints

```
┌─────────────────────────────────┐           ┌───────────────────────────────────┐
│          GitHub Pages           │           │         Render Free Tier          │
│   https://<user>.github.io/     │           │   https://<api>.onrender.com      │
│          Truthtrace/            │           │                                   │
│  - Static HTML5/CSS3/ES6        │  HTTPS    │  - FastAPI Web Service (512 MB)   │
│  - Dynamic API_BASE injection   │ ────────> │  - Lean requirements-render.txt   │
│  - Relative asset resolution    │  CORS     │  - Background Seed on Boot        │
│  - Auto-wake splash screen      │           │  - Ephemeral SQLite & In-Memory   │
└─────────────────────────────────┘           └───────────────────────────────────┘
```

### Free Tier Constraints Handled Automatically:
1. **512 MB RAM & 0.1 CPU limit:** Handled via `LOW_MEMORY=1` and `requirements-render.txt` (excludes PyTorch/EasyOCR/DETR; uses fast PyMuPDF digital text extraction, OpenCV geometric contours, and 110 DPI scaling).
2. **15-Minute Inactivity Sleep:** Handled by frontend startup splash screen that polls `/health` with a live progress indicator and retry button while the backend boots (~45-60s).
3. **Ephemeral Storage:** Handled by idempotent startup thread that repopulates SQLite tables, mock cryptographic keys, and sample documents whenever a container restarts.
4. **GitHub Pages Subpath (`/Truthtrace/`):** All frontend assets (`styles.css`, `app.js`, `vendor/*`) use strictly relative URLs.

## 🛠️ Step 1: Deploy Backend on Render (Blueprint)

TruthTrace includes a root-level `render.yaml` Blueprint specification.

1. **Log in to Render:** Go to [dashboard.render.com](https://dashboard.render.com).
2. **Create New Blueprint Instance:**
   - Click **New +** -> **Blueprint**.
   - Connect your GitHub account and select the **Sham-B/Truthtrace** repository.
   - Branch: `main`.
3. **Verify Blueprint Settings:**
   Render reads `render.yaml` and configures:
   - **Service Name:** `truthtrace-api`
   - **Environment:** Python 3.12.11
   - **Region:** Singapore (`singapore`)
   - **Plan:** Free (`free`)
   - **Build Command:** `pip install -r requirements-render.txt`
   - **Start Command:** `uvicorn backend.app.main:app --host 0.0.0.0 --port $PORT`
   - **Health Check Path:** `/health`
4. **Click "Apply":** Render builds and deploys the service.
5. **Copy Backend URL:** Once deployed, copy your Render web service URL (e.g. `https://truthtrace-api-l4cs.onrender.com`).
6. **Verify Health:** Visit `https://truthtrace-api-l4cs.onrender.com/health` in your browser. It should return:
   ```json
   { "status": "ok", "ready": true, "demo_mode": true }
   ```

## 🌐 Step 2: Configure GitHub Pages & Repository Variable

The frontend GitHub Actions workflow (`.github/workflows/pages.yml`) deploys the frontend and injects the live API URL into `config.js`.

1. **Set the API URL Variable:**
   - On GitHub, navigate to your repository: `https://github.com/Sham-B/Truthtrace`.
   - Go to **Settings** -> **Secrets and variables** -> **Actions** -> **Variables** tab.
   - Click **New repository variable**.
   - **Name:** `API_BASE_URL`
   - **Value:** `https://truthtrace-api-l4cs.onrender.com` *(use your exact Render service URL, without trailing slash)*.
   - Click **Add variable**.

2. **Enable GitHub Pages:**
   - Go to **Settings** -> **Pages**.
   - Under **Build and deployment** -> **Source**, select **GitHub Actions**.

3. **Deploy Frontend:**
   - Go to the **Actions** tab in GitHub.
   - Select **Deploy Frontend to GitHub Pages**.
   - Click **Run workflow** -> Select `main` branch -> Click **Run workflow** (or simply push any commit).
   - Once the action completes with a green checkmark, your site will be live at:
     **https://sham-b.github.io/Truthtrace/**

## ⚙️ Environment Variables Reference

| Variable | Default (Local) | Render Value | Purpose |
| :--- | :--- | :--- | :--- |
| `PORT` | `8000` | Injected by Render | Web server binding port |
| `SECRET_KEY` | (local random) | Auto-generated by Render | Session security & Fernet key derivation |
| `FERNET_KEY` | Derived / .env | Derived automatically | Document AES-256 encryption key at rest |
| `CORS_ORIGINS` | `http://localhost:5500...` | `https://sham-b.github.io` | Allowed origins for cross-origin API calls |
| `DEMO_MODE` | `0` | `1` | Enables rate limits, 5MB upload caps, security headers |
| `LOW_MEMORY` | `0` | `1` | Caps image resolutions (1600px), 110 DPI, limits thread pools |
| `DISABLE_OCR` | `0` | `1` | Disables EasyOCR/PyTorch neural networks for lean hosting |
| `LLM_PROVIDER` | `template` | `none` | Disables external LLM network queries; uses rules/templates |
| `WEB_CONCURRENCY` | `1` | `1` | Runs single worker to minimize memory usage on 512 MB container |
| `PYTHON_VERSION` | Local installed | `3.12.11` | Python runtime version specified for Render |

## 🔧 Troubleshooting

### 1. Build Failure on Render
- **Symptom:** Render build terminates with an error installing dependencies or out-of-disk.
- **Cause:** Using `requirements.txt` instead of `requirements-render.txt`.
- **Solution:** Verify `render.yaml` specifies `pip install -r requirements-render.txt`. The lean requirements file excludes heavyweight packages (`torch`, `easyocr`, `transformers`) and builds in under 45 seconds.

### 2. Out of Memory (Exit code 137 / SIGKILL)
- **Symptom:** Service restarts abruptly during document analysis.
- **Cause:** Memory exceeded 512 MB limit.
- **Solution:** Verify `LOW_MEMORY=1` and `DISABLE_OCR=1` in the Render environment variables. This activates 110 DPI rendering and 1600px downscaling, keeping memory footprint consistently below 250 MB.

### 3. CORS Error in Browser Console
- **Symptom:** Red error in developer console: `Cross-Origin Request Blocked: The Same Origin Policy disallows reading the remote resource`.
- **Cause:** `CORS_ORIGINS` in Render does not match the GitHub Pages origin.
- **Solution:** Set `CORS_ORIGINS` in Render dashboard environment variables to `https://sham-b.github.io` (no trailing slash). TruthTrace automatically supports `X-Role`, `Content-Type`, and preflight `OPTIONS` requests.

### 4. Blank Page or 404 Asset Errors on GitHub Pages
- **Symptom:** UI displays empty white screen or CSS styles do not load under `https://sham-b.github.io/Truthtrace/`.
- **Cause:** Absolute asset paths (`/styles.css`).
- **Solution:** TruthTrace uses relative paths (`styles.css`, `app.js`, `vendor/*`). In addition, the workflow injects a `.nojekyll` file so GitHub Pages does not ignore underscore directories or vendor files.

### 5. Slow Initial Page Load (1-Minute Delay)
- **Symptom:** First load after inactivity takes ~45-60 seconds.
- **Cause:** Render free tier spins down idle instances after 15 minutes of inactivity.
- **Solution:** This is normal expected behavior for Render free tier. TruthTrace frontend includes a startup splash screen that polls `GET /health` with a loading indicator and automatic retry. Once awake, response times are sub-second.

### 6. Data Reset After Server Restart
- **Symptom:** Uploaded test applications disappear after the service wakes up from sleep.
- **Cause:** Render free tier containers use an ephemeral filesystem.
- **Solution:** TruthTrace's background startup seed automatically runs idempotently on container launch, immediately restoring the 5 canonical archetype applications, mock certificates, and verification checks.
